## 2026-08-06 - Fix: DB pool created before env loads (DATABASE_URL never reached the pool)
- Reported symptom: every chat message failed with `Failed query: insert into conversations` (INTERNAL_ERROR at chat.ts, first insert of a new conversation).
- Root cause, two parts: (1) in the esbuild bundle, the `init_db()` module body that constructs the pg Pool runs BEFORE the entry's dotenv `loadEnv` calls, so the pool was built with `DATABASE_URL` missing even when the env files contained it; (2) `databaseUrlConfigured: false` at request time confirmed the key was absent from all loaded env files in this workspace.
- Fix: the api-server `start` script now pre-loads env with Node's `--env-file-if-exists` flags (weakest to strongest, later flags win): repo `.env`, repo `.env.local` (Freebuff Keys tab), then the merged `artifacts/api-server/.env` that start-dev.sh produces. Node loads these into process.env BEFORE any module code runs, so the pool gets the connection string and every module-scope env read is order-safe. No source changes needed; dotenv loading in index.ts remains as a fallback.
- Verified `--env-file-if-exists` semantics with a throwaway test (later file wins) and confirmed the flag is supported on the running Node 22.23.1. API server rebuild + typecheck pass.
- Remaining user action: add `DATABASE_URL` (existing Postgres/Neon URL) in the Keys tab; on next server start `ensureTables()` auto-creates all tables (including conversations.kind / system_prompt) so chat works immediately.
